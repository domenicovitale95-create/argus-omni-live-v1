# ARGUS OMNI — Unified Autonomous System

## Objective
One ARGUS. One doctrine. One production truth. One persistent evidence base. One learning loop.

## Core principle
ANALYZE EVERYTHING. BET ALMOST NOTHING.
FAST LEARNING. SLOW TRUST.

## System roles
- GPT/doctrine: defines reasoning, evidence standards, PRIME/VALUE/WATCH/NO BET governance and uncertainty rules.
- Backend: executes data collection, analysis, frozen predictions, settlement, calibration, historical research and health checks.
- Vercel: production runtime, Cron execution, observability, storage and deployment evidence.
- GitHub: versioned source of truth for code, governance and reversible changes.
- Autonomous auditor loop: cross-checks all declared health against production evidence and applies safe reversible engineering fixes.

## Mandatory autonomous cycle
1. Observe real production state.
2. Verify data freshness, provenance and temporal integrity.
3. Compare internal health claims with Vercel/GitHub/runtime evidence.
4. Detect incidents, silent degradation, false-green states and learning blockers.
5. Prioritize incident containment over speculative R&D.
6. Apply the smallest safe reversible technical correction on an isolated branch.
7. Validate preview/build and production after promotion.
8. Add recurrence prevention: test, guardrail, health signal or resource limit.
9. Continue evidence accumulation and scientific learning without confidence inflation.
10. Record observed evidence, root cause, action, validation, prevention and next best action.

## Fail-closed rules
If critical data is stale, contradictory, unavailable, temporally invalid or infrastructure-unsafe, affected recommendations must degrade to WATCH/NO BET rather than preserve confidence.

No subsystem can create PRIME alone. Technical health never substitutes for predictive maturity.

## Persistence and historical architecture
Historical data must be bounded and shard-based. Never deserialize the full decade archive in a serverless function. Use monthly shards, lightweight indexes, bounded batches and chronological shard-by-shard walk-forward processing. Preserve legacy archives read-only until replacement evidence is verified.

## Change safety
Safe technical repairs may be automated. Do not silently change secrets, credentials, real-money actions, staking policy, PRIME/VALUE semantics, material betting thresholds or irreversible infrastructure. Model/decision changes remain RESEARCH/SHADOW until temporally valid OOS evidence, calibration, robustness and rollback readiness are sufficient.

## Health truth
A single internal HEALTHY label is not enough. Health must be decomposed into infrastructure, deployment, API, storage, data, temporal integrity, automation, learning and predictive maturity. A false-green state is a defect.

## Learning memory
Every incident and negative experiment becomes durable failure memory so ARGUS can recognize recurrence and avoid repeating failed ideas.

## Preservation rule
Never discard validated progress during unification. Migrate incrementally, preserve existing production behavior unless a change is explicitly validated, and keep legacy data read-only until the new path proves equivalent or safer.
